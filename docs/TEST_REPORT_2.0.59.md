# PigLedger 2.0.59 — 嘉得叫料即到料

## 最終行為

依使用者指定，嘉得以已登記的叫料日期、物理料桶及數量作為實際到料來源，只登記一次。原 `feed_orders` 不搬移、不複製成另一筆 `deliveries`；既有舊到料仍保留。到料統計、盤點法實耗及料桶庫存以同一個衍生收料集合計算，每個原ID只計一次。更正／刪除原紀錄後自動回算，不維護第二份庫存數字。

快捷的「叫料」「到料」兩種用語都儲存到同一份原叫料資料。一般表單、整批與照片待確認沿用原交易、稽核、預覽及冪等流程。照片未明確確認前不算到料。舊的直接新增到料API在此模式拒絕另建第二筆；舊到料歷史的更正仍保留。

未來日期標示「預定到料」，查今天的統計／庫存不提前計入；到紀錄日期才納入。安全容量檢查也涵蓋相關日期。單筆／整批／照片核對顯示容量提醒，若同日已有原筆而選擇另加一筆可能超容量，會另外說明。快捷仍需勾選警告才可確認。

共享桶全量只進一次桶庫存；各棟實耗未分配時仍顯示未知，不自動平均。單棟或已明確確認各批分量的收料可用於原盤點法。實際到料不等同已吃掉：沒有實耗／剩料或可靠重量校正時，正式FCR仍不猜值；到料量估算維持粗估標示。未啟用庫存、沒有容量或盤點基準時，不填假庫存。

畫面統一為「飼料登記／飼料到料紀錄」，移除重複的到料空卡片及統計欄位，保留中越語。14棟簡寫、每日核對、未啟用LINE不顯示、原通知與其它頁面延續。

## 實作與資料庫

- `app/feed_receipts.py`：環境規則、從原紀錄衍生收料、預覽容量警告。
- `app/bin_stock.py`、`app/server.py`、`app/operations.py`、`app/order_fcr.py`：統計、庫存、盤點法、FCR、作廢預覽及CSV使用同一收料來源；client snapshot附計算視圖與模式旗標。
- `app/quick_record.py`：文字用語歸到原單一資料表，保留容量及防重複確認。
- `app/feed_review.py`、`app/feed_drafts.py`：原單筆、整批、照片確認保留同一交易；預覽綁定相關農場版本與容量狀態，舊預覽遇異動拒絕寫入。
- `app/static/feed-receipts.js`、`feed.js`、`bin-stock.js`、`quick-record.js`、`feed-review.js`、`feed-bulk.js`、`feed-drafts.js`、`app.js`：單次登記文案、未來日期標示、確認警告、原實耗畫面與新收料視圖。
- `tests/test_feed_receipts.py`、`tests/feed_receipts_browser.py`：SQLite／Turso介面與真實瀏覽器驗收。
- 其餘為版本2.0.59、快取、新資源載入、檢查指令及操作文件。

schema 4不變，無新增表、欄位或遷移，正式農場原紀錄未由本次開發重新寫入。此為牧場業務規則：原Vercel專案正式環境啟用非機密變數 `FEED_ORDERS_ARE_ARRIVALS=1`；未啟用的其它部署保留原叫料／到料分開模式，並有回歸驗證。庫存仍從有效原紀錄計算，備份維持原始ID與來源。
