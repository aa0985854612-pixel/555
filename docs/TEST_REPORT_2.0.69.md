# 2.0.69 — 備註用滿框內空間，避免文字擠上方、下面大片留白

使用者提供9棟、23棟的實際紙本畫面：9棟的13筆死亡被提早拆成兩小欄，23棟7筆也只在上方，兩棟下方另有一個未標示的大空框；出豬字體同樣未使用剩餘高度。

`app/static/weekly-pdf.js`保留單頁規劃的最低必要空間估算，實際繪製改為：

- 每棟用整個可用高度直排，只有以原可讀字級真的放不下，才使用自己的右側欄。取消實際版面的「超過8行就分欄」行為。
- 各棟與出豬區獨立量測可用空間，備註從原8.5pt依空間放大，最高13.5pt。先選定可容納的欄數，放大不會反過來強迫多分一欄。
- 多筆紀錄按可用高度調整行距，保持第一筆在上方，最後一筆接近框底；只有一至三筆時保留自然間距，不將兩筆拉到整框兩端。
- 各棟框線延伸至整個備註框底部，多棟時分配各列高度，移除下方未標示的空白矩形。
- 固定一頁A4、原始數字逐筆保留、淘汰不印、PDF／預覽／瀏覽器列印共用內容的規則不變。

除了版本／快取標記與文件，只修改PDF前端排版，沒有後端邏輯、資料庫、正式農場資料或環境政策變更。平均分料、現況總覽與歷史入口保留。

驗證：

- `tests/weekly_one_page_barns_browser.py`：4個情境通過，8棟／14棟正常資料不提前分欄，字體按空間放大；190筆飼料、120筆出豬與100筆死亡、四棟分區仍一頁且完整。
