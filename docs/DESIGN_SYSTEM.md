# 嘉得管理介面設計規範 · 2.1.6

本次直接整合既有六頁應用程式。`app/static/design-system.css` 是共用畫面規範，`app/static/workspace-ui.js` 是共用互動元件；既有資料模型、寫入流程、公式、權限、雲端同步與紙本產生器沿用原實作。

## 設計判斷

原介面的問題是不同版本累積的字級、卡片、操作區與強調色競爭；手機把完整桌面表格擠進窄畫面，篩選和數字遮過真正的工作入口。新版以登記、查核、查詢三種工作需求安排資訊，只有主要輸入表單、整合統計列和需分組的批次使用白底容器；其他列表以對齊、標題與分隔線組織。

## 共用規格

| 規格 | 採用值與用途 |
| --- | --- |
| 字體 | 系統字體、Segoe UI／Noto Sans TC 後備；不下載外部字體 |
| 基準字級 | 中16px，小15px，大19px，保留裝置字級偏好 |
| 文字階層 | 頁標題24px／手機約21px，區塊16px，操作與表格13–14px，輔助11–13px；主要表單與手機輸入框至少16px，桌面清單工具14px，主要數字約26–29px |
| 行高 | 一般1.5，說明1.6–1.65；數字使用等寬數字特性 |
| 主文字／次文字 | `#202b33`／`#69757b` |
| 強調色 | `#234f83`；主要操作、選中導覽與焦點；依使用者要求採藍色，不作大型彩色背景 |
| 底色／表面／分隔 | `#f6f7f8`／`#ffffff`／`#e1e6e7` |
| 狀態 | 錯誤`#ad3947`，警示`#896323`；同時使用文字，避免只靠顏色 |
| 間距 | 4、8、12、16、24、32px；同類區塊遵守同一節奏 |

| 陰影 | 一般內容不使用；只保留浮動字級選單、提示與視窗 |

避免各頁自行增加新主色或大型獨立數字卡。新增畫面應使用現有 `.ui-surface`、`.filters`、`.ui-query`、`.actions`、`.table-wrap` 與共用文字規格。新增紀錄清單可透過 `enhanceTables()` 的目標容器接上現有搜尋、排序及分頁元件，不能另造資料來源。

## 版型與工作流程

- 桌面：64px頁首、208px側欄，內容上限1360px；701–1119px改164px側欄。六個入口與既有網址雜湊保持一致。
- 手機：700px以下改六格固定底部導覽；處理安全區、鍵盤焦點捲動與PWA獨立模式，所有分頁同時可見。
- 每日登記：日期靠近表單標題，出豬地點保留在主表單；寬螢幕把登記與當日核對並排，全場總覽維持獨立切換。
- 總覽：四項指標共用單一中性色統計列；手機為二乘二。批號、剩餘、育成率與各棟資料採一致的密度。
- 統計：上方查詢、期間合計、FCR與到料估算、各批死亡明細分層；比較長條只使用後端已知死亡數，不補造資料，也不修改統計。
- 歷史與到料／用料明細：桌面使用原表格；手機把每筆改成帶欄名的紀錄列。搜尋、數字排序、每頁25／50／全部與上下頁共用一套元件，保留原筆編輯／刪除按鈕。
- 飼料：日期、數量、棟批與料桶先行；維持多筆暫存、原核對畫面、料別記憶與人工分配。未設定LINE及未啟用功能仍按原條件隱藏。
- 秤重：輸入作業優先，估算輔助；寬螢幕並排，手機可快速跳至估算。保留逐頭／合計兩種模式與各次作業歷史。
- 設定：批次／棟舍管理先行，其他維護保留原可展開區塊、編輯權限與稽核紀錄。
- 登入與開通：共用輸入及按鈕；保留原帳號、豬場圖示與封面。

## 互動與可及性

焦點外框、跳至主要內容、目前頁面 `aria-current`、表格排序 `aria-sort`、載入狀態 `aria-busy` 與原生欄位驗證共用處理。驗證錯誤直接關聯對應欄位；修正後移除過期關聯。手機表格保留欄位標籤及可操作排序控制。減少動態效果偏好會停用進度動畫與平滑捲動。

新增表格搜尋、排序與分頁只作用於目前伺服器查詢結果；CSV仍依原篩選匯出完整結果，不截成目前頁。刷新資料時保留清單搜尋、分頁、排序與搜尋焦點；原未儲存表單的數值、料別、地點及選擇不因版型重排而清空。帳號切換後清除上個帳號的清單狀態。

寫入中顯示進度，成功／失敗沿用原正式回應與重試機制；不以動畫或時間推測成功。原子寫入、同鍵重試、權限與衝突檢查仍由既有程式負責。

## 資料、列印與快取邊界

資料庫結構與業務計算保持；2.1.5在既有棟舍CRUD路徑開放管理員刪除未使用棟舍，沿用原交易、關聯驗證、版本衝突、稽核與同鍵重試，其他紀錄仍走原作廢流程。螢幕樣式全部位於 `@media screen`，2.1.1同步修正A4畫布：週表維持正常字級與宣告列高，備註共用最多8pt及固定行距，先利用右側續欄。只在週表自身內容過密時縮排週表；所有紀錄、逐次售出、未來日期及無CSV規則保留。

PWA識別、scope、start_url、獨立模式與圖示沿用；只更新主題色及版本化CSS／JS快取。Service Worker既有通知與安全更新流程保留，不強制重載正在輸入的表單。

## 2.1.3已結束紀錄

歷史紀錄以可展開的「已結束紀錄」提供獨立清單；展開時專心顯示已結束批次，查看原紀錄或收合後恢復原查詢。設定提供同名入口。依原批次狀態即時索引，按原批號歸組、列棟舍與進場日期，可搜尋。只顯示使用者原有權限的查看／列印／管理操作；不新增、搬移或複製紀錄。正常肉豬報表只提供飼養中批次／棟舍，歷史開啟的報表則使用已結束範圍，模式在下次普通開啟時重設。

## 2.1.4棟舍選擇

棟舍選單與料桶設定的棟舍勾選共用`orderedBarns()`，依名稱開頭棟號排序（含第字、全形數字的正規化），不修改原名稱或ID。沒有號碼的自訂名稱保留在數字棟舍之後。肉豬紀錄表仍先選批號，再列該範圍的棟舍，範圍內同樣按號碼排序；已結束與飼養中的選擇規則維持。

棟舍設定的獨立清單共用 `orderedBarns()` 數字排序，不重新排列批次分組。每筆管理操作提供44px以上的更正／刪除按鈕；刪除使用獨立原生對話框、原名稱及關聯清單，不與登記紀錄的作廢視窗混用。中越語共用相同版型。

肉豬A4使用`#b42332`呈現死亡週數、死亡備註及死亡合計，標題與其他資料保持原色。淘汰只加入上方週欄，與下方三項合計分開；不新增淘汰備註。HTML明細與PDF畫布使用相同色值，列印沿用PDF內嵌圖片，不另排版。
