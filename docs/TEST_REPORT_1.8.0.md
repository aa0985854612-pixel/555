# PigLedger 1.8.0：單一叫料量登記

飼料日常改為一張表單：日期、叫料量、公斤／噸；廠商、料別、單棟批次、備註選填。下面共用查詢與叫料合計，清單採卡片，支援更正、CSV、歷史類型切換及管理員作廢。原到料／用料若存在，收進歷史展開區；原表單只在更正既有舊紀錄或重試原本未確認的舊筆時開啟。

新增獨立feed_orders紀錄，沿用通用records表與schema4，無SQL結構／環境變數／資料搬移。叫料不是到料或實際耗料，不會進入庫存換算、ADG或FCR，也不產生自動下單、配送或預測。無可靠耗料仍顯示資料不足。保存新叫料後，必須使用1.8.0以上讀取資料及備份，不能退回不認識新類型的舊程式。

## 本地與模擬測試

- `sh scripts/check.sh`：233項單元／整合測試及6份JavaScript語法檢查通過。新增18項叫料測試，其中9項本地SQLite，9項經模擬Hrana遠端交易。
- 新測試涵蓋叫料與舊類型隔離、實耗／FCR／存欄不受新增修改作廢影響、缺實耗不計FCR、重送不重複、舊revision拒絕、編輯／唯讀權限、日期及批次篩選、無效數量、入場前叫料、備份重匯。
- `tests/feed_orders_browser.py`：13組真實Chromium／隔離SQLite／HTTP情境通過。日常只有一張叫料表單、一般開頁只讀取一個叫料清單API；舊歷史展開時才額外查到料／用料。
- 驗證公斤／噸換算、保存保留日期及單位、同筆更正、三輪語言／背景同步保留草稿及焦點；伺服器已保存但回應遺失、重新載入再重試，只留下原一筆。CSV標示feed_order，單棟資料匯出可讀棟舍／批次。
- 實際比較：合成場原實耗2000公斤、增重1000公斤，FCR為2；新增、更正與作廢叫料後仍為2。舊到料與實耗紀錄ID保留。作廢後列表立即刷新，切換帳號先清除上一角色的操作按鈕，再載入新角色資料。
- 唯讀不能儲存；編輯可新增及更正自己叫料、不能作廢；管理員作廢需預覽及原因，舊值與操作歷程保留。透過直接HTTP繞過按鈕的寫入／刪除也被伺服器拒絕。
- 4種寬度×2語言×3字級，共24種飼料版面無整頁水平溢出，日常維持單一表單。
- `tests/period_deaths_browser.py`：8組死亡清單回歸通過，含36種版面，零死亡隱藏等功能保留。
- `tests/pwa_test.py`：5項新版快取、草稿保護與API不快取等檢查通過；新版資產清單包含feed.js。

Hrana測試使用本地模擬服務，不能當作真實Turso驗收。手機為Chromium視窗／觸控模擬，Safari與實體iPhone仍待驗收。未使用真實使用者密碼互動登入。

## 正式備份與雲端驗收

修改前已備份原Turso：58筆records、4個帳號。當時正式到料及實耗各0筆，沒有將舊資料重新標成叫料，也沒有建立公開預設密碼。沿用原GitHub main、Vercel專案、正式HTTPS網址、Turso及原帳號。

正式部署驗收檢查版本與feed.js等HTTPS資產，並核對新介面程式與Git內容相同。Turso儲存驗收在單一BEGIN IMMEDIATE交易內寫入極小量的暫時叫料及操作紀錄，讀回新類型並核對存欄、到料、實耗及FCR完全不變，最後明確ROLLBACK；以原資料、帳號及安全設定指紋核對沒有永久測試資料。具體結果保存在私密維護驗收檔，不將維護程式或農場資料放進程式包。

臨時維護部署驗證完即清理，原網域指向Git正式部署。使用前先完成未儲存內容，再到「設定→套用更新」確認1.8.0。
