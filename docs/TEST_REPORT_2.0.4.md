# PigLedger 2.0.4：人工來源歸屬與可靠單棟存欄

批次可保存管理員確認的來源異動歸屬及原因。核對項目以原來源ID、日期、類型、數量、批次與儲存格定位；只接受原本未指定棟舍的整筆來源事件，目標必須是該來源的原批次成員。保留來源原檔、報告、數量、日期及原事件ID，不另外建立死亡或出豬紀錄。來源內容變更不符合核對身分時，保留待核對，不套用舊歸屬。

舊來源基準內已包含的死亡只補分棟，不再次扣頭數。歷史、單棟死亡、育成率與CSV沿用同一來源歸屬。來源作廢沿用穩定事件錨點，重新匯入補上原棟別也不會使已作廢事件復活。

使用者確認進場數可靠且沒有轉棟後，可保存存欄重建依據。僅當整批每棟都有進場頭數、完整分棟的死亡／正常出豬／淘汰，且各基準日期的整批頭數均能核對，才用進場減已知出場重新分配舊暫估存欄。整批與全場合計不變。資料缺漏、合計不符或資料矛盾時保留原存欄並提示待核對；不平均分配、不倒推入場分母。

新欄位皆為可選的批次JSON欄位，沿用schema4，不重建資料庫。管理員權限、revision及原寫入稽核／重送保護沿用伺服器規則。舊客戶端未傳新欄位時保留已核對內容，備份及重複還原保留人工歸屬和原始來源。

## 驗證

- 378項單元／整合測試與11份JavaScript語法檢查通過。
- 新增26項（SQLite13＋模擬Turso HTTP13）涵蓋來源ID及全場數量保留、基準死亡分棟、同鍵重試、舊客戶端、角色及revision、偽造內容／錯批／重複歸屬拒絕、備份還原、作廢後原來源補棟不復活、完整明細重建、缺漏或整批矛盾時保留原存欄及重複讀取。
- 真實Chromium／本地HTTP／合成資料3組通過：管理員HTTP補正保存、實際歷史及CSV只出現原單一事件、手機視窗歷史顯示及重新載入不重複。
- PWA5項更新及草稿保留通過。
- 真實Turso先以單一交易預演與ROLLBACK；正式套用前另備份，只更新經核實批次的來源核對與存欄依據，逐筆比對其他紀錄、帳號與原來源不變。正式版本、歷史查詢、育成率與全場／各批次合計另以重新連線核對，收據保存在私密維運目錄。

仍缺棟舍或現場資料的來源保留未指定。未進行實體手機、原生Safari、客戶密碼互動登入或實體列印驗收。
