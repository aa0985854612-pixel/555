# 資料保留、 schema 與計算口徑

版本1.0.0，SQLite schema 2。建立專案前檢查 `/workspace/555`、Git 追蹤檔、工作區與部署變數名稱：儲存庫沒有提交、程式碼、資料庫、帳號、歷史資料或既有雲端服務。使用者確認沒有既有系統並選 Docker 交付。因此本次没有正式舊資料可遷移，沒有清空或刪除農場資料。所有示範及測試資料使用隔離暫存資料庫／專用 Docker 測試 volume，不放進交付包。

## 儲存結構

- `records`：棟舍、批次、異動、到料、耗料、秤重，共用永久 UUID； revision 與刪除墓碑。
- `users`：原帳號 ID、名稱、scrypt 密碼雜湊、admin/staff/viewer、啟用與 revision。
- `sessions`：僅存隨機 session token 雜湊、CSRF token、期限。Cookie HttpOnly/SameSite/正式環境Secure。帳號停用或修改權限／密碼後撤销該帳號既有登入。
- `requests`：使用者與請求識別碼唯一，記請求指紋、原結果；同 key 改內容拒絕。
- `audit`：時間、操作者、動作、資料種類／ID、前後值。帳號操作不記明文密碼或雜湊。

寫入使用 `BEGIN IMMEDIATE` 交易，權限、日期、容量、分配、重疊及版本檢查與入帳在同一交易內。任何失敗都回滚，不产生半筆資料。不同人重送同一事件且沒有共用識別碼時，匿名頭數無法辨識實際個體；人員仍須避免把同一頭豬／同一事件另建紀錄。介面將sale/cull/death設成單選，不會自動二次扣頭。

## schema 更新與備份

首次建立 schema2。schema1→2 只新增 users.revision；更新前以 SQLite Backup API 备份整庫，帳號、雜湊、所有原始紀錄及歷程不变。具體已用模拟 schema1 跑實際遷移、驗證前後資料和備份檔。資料版本高於2則拒絕啟動，不降版重建。

下載備份前建立SQLite檔案備份。JSON備份包含全部原始紀錄、刪除墓碑、帳號雜湊及操作歷程；不包含可重用登入Cookie。匯入前先整庫備份，在交易中驗證：新ID加入，相同／較舊ID跳過，較新版或同版本不同內容拒絕。現在的更正及已刪除資料不會被舊備份復活。恢復到新資料庫會保留原帳號與歷程；目前資料庫已有帳號的角色／密碼不以匯入靜默覆蓋。

## 頭數及日齡

剩餘＝進場＋外部補豬＋轉入－轉出＋盤點增減－正常出豬－淘汰－死亡。

合計出豬＝正常出豬＋淘汰；育成率＝(統計分母－死亡)/統計分母。分母為所選範圍進場＋外部補豬＋跨範圍轉入；同選定範圍內的轉棟抵銷，全場不重複算進場。盤點只改存量，不假設增加了外部進場，也不假設所有減少都是死亡；需要以真正事件更正才能影響育成率。分母0顯示—。

轉棟是單筆連動來源與接收批次，驗證為同 cohort。接收初始0頭，來源日齡與依據日期承接，不重新起算。管理員明確修正接收日齡時優先保留。缺可靠日齡維持空值；目前日齡＝參考日齡＋參考日期後天數，週齡除7。

日期統計只計當日及之前事件；更正回溯日期時也檢查後續各日期餘額不得負值。新批舊批以永久ID分開，不因同棟而混算。沒有外部原系統的未歸屬舊資料可供本次驗證；未來遷移未知歸屬應保留未指定，不能任意插入新批。

## 飼料與重量

以公斤儲存，顯示噸時除1000，切換單位不改物理量。到料獨立於耗料，分配完整合計或保持共同未分配。庫存法依所選批次、選填廠商／品項的真實分配到料計算；共同未分配資料不自行套用。庫存法原料存量需對應同一分類。

耗料期間 `[start,end)`，同批已採用期間不得重疊。異常負數保留與標記，不歸零。更正到料後，庫存來源動態重算，不改寫原剩料紀錄；直接來源不受新到料數量取代。查詢的跨界耗料不按天數亂拆分。

秤重保存原數字與各筆來源；個體列表可推導頭數及總重。合併＝总重／總秤重頭數，保留同日多筆。ADG同批不同日期，(後均重－前均重)/天數，抽樣估計保留負值並提醒。FCR＝實耗/活體增重；代表性勾選是人員判斷，軟體不能驗證抽樣品質。移出含出豬、淘汰、死亡與轉出，移入含補豬和轉入，需各筆實際活體總重。盤點、端點同日不知異動先後、缺數據或非正增重都不產生正常FCR。多批合併不得平均各FCR，也不得把不完整批次當0。

浮點原值不因UI四捨五入而改寫；畫面頭數整數、重量/ADG/FCR通常2位。備份保留原始完整資料，CSV包括來源與單位。
