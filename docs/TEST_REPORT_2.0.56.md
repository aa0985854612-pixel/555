# PigLedger 2.0.56 — 快捷儲存後的當日回報

## 問題與修正

舊版快捷紀錄的日期與「當日核對」各自獨立。補登昨天，或核對區原本選了其他日期時，儲存雖然成功，核對區仍顯示舊日期的頭數；「當日已登記」明細也預設摺疊。

現在快捷豬隻異動確認儲存成功後，核對區自動切至該筆日期，重新取得該日資料，更新死亡／出豬／淘汰總數並展開明細。修改日期、數量、刪除與同鍵重試成功同樣適用。進豬可在當日明細看到；原存欄統計照常更新。飼料維持原分類，不當成豬隻頭數，也不改變核對區日期。

僅依正式儲存成功事件更新；辨識預覽與儲存失敗不會顯示為已回報。原手動表單未儲存的內容保留，避免重複輸入。其他裝置原有同步仍更新當前所選日期，不因別人補登而跳日期。

## 修改檔案

- `app/static/review.js`：接收原有快捷成功事件，對齊核對日期與展開明細；原請求序號保護避免較舊回應覆蓋新日期。
- `tests/quick_daily_sync_browser.py`：真實 Chromium／HTTP、合成資料的八項回歸驗證。
- `tests/daily_review_browser.py`、`tests/test_upgrade.py`：更新舊測試定位器與精確來源檔案比較，消除與本次修正無關的既有測試失敗。
- `VERSION`、`pyproject.toml`、`Dockerfile`、`app/store.py`、`app/static/app.js`、`app/static/index.html`、`app/static/sw.js`：版本及快取更新至 2.0.56。
- `README.md`、`docs/USER_GUIDE.md`、本報告：操作說明與驗收。

## 驗證

新測試已先在舊版重現失敗：補登昨天死亡 3 頭後，核對日期仍停留今天。修正後檢查：

1. 補登昨天死亡 3 頭，切換日期、顯示 3 頭與展開明細，保留原表單未送出的 17 頭，不重複寫入。
2. 接著新增今天出豬 4 頭及淘汰 2 頭，回到今天並立即更新畫面數字。
3. 歷史更正死亡為前天 2 頭，顯示正確日期與數量，原日期歸零。
4. 刪除後受影響日期歸零，明細移除。
5. 飼料叫料不改變核對日期、不增加豬隻異動數。
6. 只有預覽或回傳 409 時，已回報數不變。
7. 伺服器已儲存但回應遺失，重新開啟網頁並重試原筆，顯示補登日期且只有一筆。
8. 越南語、390px 手機版及瀏覽器錯誤檢查。

驗收結果：728 項單元／整合測試全部通過，所有 JavaScript 語法檢查通過；8 項新增快捷回報測試、16 項原快捷紀錄測試、9 項每日核對瀏覽器回歸，共 33 項瀏覽器情境通過。測試全部使用隔離的合成資料，沒有在正式農場新增測試豬隻或飼料，也未發送通知。

## 資料庫與部署

schema 4 不變，無新增表、欄位或遷移；既有紀錄與庫存不需重寫。使用原 GitHub → Vercel 部署流程，確認正式部署 READY、commit、原專案與正式網址對應，保留台灣每日 10:00 提醒。瀏覽器驗證為本機 HTTP 合成資料；未從此環境登入正式農場操作。

更新後若手機仍顯示舊版，先保存未完成輸入，再套用網站的新版本提示。

每日核對舊瀏覽器測試曾停在已不存在的 `#quality-panel`。本次改用現行「批次與棟舍管理」入口驗證原進場數未變；此為測試定位器更新，未修改設定頁功能。

完整單元測試另發現舊測試用兩次產生的 XLSX ZIP 位元組比較，在跨過 ZIP 的兩秒時間邊界時偶發失敗。已改為比對「實際提交檔案」與「保留的來源檔案」位元組，維持來源完整性檢查；未修改匯入程式。
