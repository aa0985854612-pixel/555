# PigLedger 1.9.0：每日核對、巡場確認與待補清單

沿用原六頁、原ID、帳號、歷史、同批歸組與正式網址。新增巡場紀錄儲存在既有records資料表的daily_checks類型；schema仍為4，無新資料庫、無帳號重設、無進場或存欄數字回填。更新前完成原始碼封存及私密Turso備份。

## 行為與資料邊界

- 每日登記下方顯示所選日期的死亡、正常出豬與淘汰已登記數，展開可逐筆核對與沿用原更正／管理員作廢流程。切換核對日期不改正在填寫的表單。
- 巡場按日期＋單棟批次保存「已巡場、無死亡」，不當作死亡0隻異動、不改存欄或育成率；沒有紀錄顯示尚未回報。有死亡或未分配死亡時不能確認無死亡。來源基準期與未來日期不可補成無死亡確認。
- 同一棟批日限一筆，連按／並發／斷線使用原有持久化冪等請求。修改需revision；編輯僅可撤銷／重新確認自己建立的確認，管理員可處理他人紀錄，唯讀禁止寫入。撤銷需要原因，原值及操作者時間保留於audit。
- 補登死亡在同一交易撤銷先前的無死亡確認並留下稽核；之後作廢該死亡，不會自動復活先前確認。需要人員再次巡場確認。
- 設定頁集中列出在養單棟進場數、入場均重、日齡、死亡分配及存欄缺項，或存欄超過可靠進場分母的核對提醒。來源缺日期、缺棟批、只有均重沒有樣本數、未解決來源衝突及未歸屬叫料保留原內容。管理員可直接開啟原批次編輯，不猜填資料。
- 週期統計、週表與CSV另列巡場涵蓋及「未回報不代表無死亡」。涵蓋只計目前在養批次、各自進場／來源基準後的棟批日，死亡登記不代表完整巡場；不把歷史來源快照改成逐日確認，也不變更原死亡或育成率公式。

## 本地與模擬測試

283項單元／整合測試與10份JavaScript語法檢查通過。新增26項（本地SQLite13＋模擬Turso HTTP13），涵蓋零值語意、同批不同棟隔離、未來／進場前／來源期限制、角色與擁有人、過期revision、同鍵重試與不同鍵重複、並發、關聯保護、補登死亡與撤銷不復活、備份重複還原、缺項清單與唯讀計算。

真實Chromium＋HTTP＋合成資料：9組每日核對情境通過。3輪輸入、語言切換、同步與儲存，每輪1次snapshot讀取＋1次movement寫入；量測整段操作277／282／255ms，日期／棟舍／批次保留。這是本地測試環境整段操作耗時，不能當作真實雲端回應時間或手機實機速度。模擬伺服器已成功但回應遺失，確認顯示待重試且同鍵重試不產生第二筆。

回歸：10組每週報表、飼料簡寫／CSV／短期及39週直式一張A4；7組iPhone尺寸／觸控／safe-area／字級與語言／儲存；4組跨日同批歸組；5項PWA更新與草稿保護。320、390、768及1366寬度的新核對介面沒有整頁水平溢出。

## 真實雲端與正式部署

部署使用原GitHub main、原Vercel專案及Turso。透過私密建置程序對正式Turso讀取與驗證原資料、帳號及1370整批進場數，並用明確ROLLBACK的真實交易驗證daily_checks寫入／讀取及稽核SQL；不提交測試巡場紀錄。正式HTTPS資源、版本與未登入API限制另行讀回，部署收據與備份識別保留於私密維運目錄。

未使用客戶密碼測試互動登入；未完成實體iPhone／Android、原生Safari、實體鍵盤及印表機驗收。本地尺寸／觸控模擬不代表實機測試。新增功能本身不會自動幫農場確認任何一天的巡場。
