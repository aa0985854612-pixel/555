# 2.0.53 每日飼料照片先待確認

依使用者要求，照片轉錄先存入獨立feed_drafts，狀態pending不計入正式feed_orders、叫料合計、估算料肉比或每週報表。可跨日期、保留來源檔名、未辨識提示及未填欄位，支援修改／不採用／已正式登記歷史。現階段採聊天傳照片，由助理整理成網站待確認清單；網站不宣稱已有圖片自動辨識服務。stage_feed_photos.py只建立草稿，使用內容固定冪等鍵，不提供直接確認功能。

正式確認需目前revision、與資料版本綁定的preview_token及confirmed=true。逐筆比較同日同桶原紀錄；唯一原紀錄預選更新，多筆／作廢／重複項目需明確決定，另次叫料需明確選擇。保留原有備註及已確認的bin_allocations；總量改變而分配不符時禁止確認。整張清單在同一交易內新增／更新正式叫料，再標記confirmed及紀錄操作者、時間、正式ID；同鍵重試不重複加量，並行更正使舊預覽失效。

網站新增每日飼料登記區、可編輯逐筆表單、原噸數到新噸數比較、勾選核對及正式確認按鈕；更改輸入或伺服器拒絕舊預覽時清除確認。來源及用藥完整列出，分配數量可一併核對。草稿持久化，裝置上的未儲存修改以帳號隔離，唯讀及非建立者權限由伺服器保護。一般records變更API不能直接寫草稿狀態。備份可保留pending／confirmed；SQL資料表及schema版本4不變，含草稿的資料需使用2.0.53以上版本。
