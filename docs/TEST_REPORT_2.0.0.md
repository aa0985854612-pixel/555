# PigLedger 2.0.0：三種料別、廠商與共用／雙料桶

沿用六頁、正式網址、原帳號、所有歷史與schema4。新增feed_bins紀錄類型及可選的新叫料欄位，不重建資料庫，不把既有叫料、到料或耗料改寫成新的料桶紀錄。

## 已確認的設定

養全：1、2、3、4、8、9、12、14、18、21、23、24棟；其餘為新農科。以使用者文字回覆為準，照片不清楚的欄位不猜填。

共用桶：1／2、3／4、5／6、16／17。11、14、15棟各有兩桶，分別命名11-1／11-2、14-1／14-2、15-1／15-2；其他棟一桶。共23個料桶（養全11桶、新農科12桶）。料桶不是新棟舍，不合併棟舍ID、批次或存欄。

## 行為

- 日常叫料選料桶、料別（大豬料／仔豬料／哺乳二期料）、廠商、日期及公斤／噸。選桶帶出廠商，可明確修正本筆實際廠商。每個桶的棟舍可對應各自批次；只有當日有唯一在養候選時自動帶入，其他情況保留未指定，不猜批次。
- 既有未指定料桶紀錄與舊料名保留，可在編輯時看到原料名；不強迫回填新分類。新料桶登記由伺服器驗證三種料別、桶別、參照、權限與revision。
- 共用叫料保存一筆原始數量、料桶／棟舍快照及明確批次ID，不創造分棟公斤。查完整且已確定的同批範圍只計一次；單棟、跨批或歸屬不足時，整筆量列為共用／待分攤參考，可歸屬合計另外顯示；週表合計為—並列已知量，不擅自平均或各棟算全量。全場合計每筆只算一次。
- 11-1／11-2等雙桶各自登記，同棟範圍合計兩筆。支援料桶、料別、廠商及原日期／棟舍／批次篩選；歷史及CSV沿用同一範圍。CSV清楚區分原整筆量與空白的未分攤單棟量。
- 肉豬每週紀錄表上方增加棟舍預設廠商、本期間實際登記料別及有資料時的登記廠商。預設值與歷史實際值分開，變更設定不回寫舊紀錄。欄內沿用日期＋噸數（桶／棟）並標記共用，未分攤另列。
- 設定增加可展開的料桶／廠商管理。僅管理員可修改；已有叫料的桶不能直接改棟舍歸屬，可停用後另建。變更名稱或廠商保留原叫料快照，避免歷史被重新命名。唯讀／編輯不能繞過伺服器管理限制。
- 叫料不當作到料或實際耗料，既有ADG、FCR、頭數、死亡、出豬、淘汰、育成率及巡場不變；沒有自動叫料、配送或採食預測。

## 測試

337項單元／整合測試、11份JavaScript語法檢查通過。新增32項（SQLite16＋模擬Turso HTTP16）：全部23桶與廠商、三料別、完整同批一次計入、單棟／跨批不分攤、雙桶、缺批次、舊新批隔離、不合法參照與重複、快照防偽與保留、引用鎖定、角色／revision、同鍵重送、備份重複還原、頭數與耗料不變、週表上方供應商／料別及舊文字保留。後續小修重新執行相關32項，全部通過。

真實Chromium＋HTTP＋合成資料10組料桶情境通過，涵蓋三輪語言／同步保留草稿、一次叫料對應兩棟、雙桶分筆、週表上方及共用簡寫、實際CSV、直式一張A4、單棟未分攤、歷史編輯、設定與唯讀直接API403；24種尺寸／語言／字級組合無整頁水平溢出。

回歸：原13組叫料（含失去成功回應、重新載入與重試不重複、原實際FCR維持）、10組週表／CSV／短期及39週各一張直式A4、9組每日核對、7組iPhone尺寸／觸控／safe-area與5項PWA更新草稿保護。

## 正式資料與限制

更新前原始碼封存與私密Turso備份。真實Turso以一個交易預演23桶及逐筆稽核後明確ROLLBACK，再重新連線確認全部原紀錄／帳號／requests不變；正式程式部署後才以穩定ID、可重複執行的設定程序套用，避免舊版本無法讀取新紀錄類型。

套用前另做同交易內備份；僅新增料桶設定及其稽核。既有頭數、批次、舊叫料、異動、秤重、來源Excel、帳號與請求收據逐筆比對保留。照片僅作配置參考，未將照片的手寫數量任意新增為叫料。正式HTTPS、資源版本、登入限制與Turso重新讀回另行驗證，收據與備份識別保留於私密維運目錄。

未完成實體iPhone／Android、原生Safari、實體印表機及使用客戶密碼的互動登入驗收；本地尺寸／觸控模擬不代表實機，Chromium產生的A4 PDF不代表已實際列印。
