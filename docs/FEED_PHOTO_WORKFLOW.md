# 照片飼料登記：先待確認，再正式登記

這是使用者於2026-10-24明確指定的新流程，適用於之後收到的飼料照片。先前已完成的正式紀錄不回退或重新建立。

收到照片後，先逐筆擷取到料日期、時間、廠商、料桶／棟舍、料別、噸數、用藥及卸料備註。依照片正文日期，不能把聊天日期當到料日；藥名及kg／ppm照原文保留。共用料桶總量只登記一次，不猜分攤；已有明確bin_allocations則保留。卸不下改卸另一桶的備註，不能變成第二筆噸數。

只建立feed_drafts的pending清單。可透過登入後的POST /api/feed-drafts，或scripts/stage_feed_photos.py，在已授權的同一農場環境建立。雲端操作前確認正式網站已是2.0.53以上，因舊版不認識新草稿種類。腳本只呼叫save_draft，沒有確認或直接寫feed_orders的功能；相同內容重試採固定冪等鍵。未辨識清楚的欄位留空並註記，留給使用者修改，不猜日期、數量或料桶。

清單可以跨日期；建立後告知使用者逐筆整理結果和合計，問「這樣有沒有寫錯？」。等待使用者在對話明確確認，或在網站「飼料紀錄→每日飼料登記」核對、勾選並按「確認正確，正式登記」。收到照片本身不代表確認，操作人不能自行確認。確認前不得呼叫finish_draft、feed-order-apply、bulk-apply或直接新增／更正正式feed_orders。

若使用者在對話明確批准已列出的清單，可讀取當前草稿、重新preview並確認同一版內容後，執行其已批准的正式登記。若數量、日期、料別或所更新的原紀錄發生改變，先重新列出差異核對，不能沿用舊確認。網站會顯示新增／更新、原噸數到新噸數、用藥備註及原已確認分配；多筆原紀錄、作廢紀錄或清單重複必須明確決定。

待確認與不採用清單不進叫料合計、估算料肉比或每週報表。正式確認是單一交易，寫入所有新增／更新後才將清單標成confirmed，保留操作者、時間、正式紀錄ID與原始差異稽核。同一確認重試不可重複加量。若使用者要修改或不採用，可在正式確認前編輯或取消。

腳本輸入範例：

```json
{"title":"10/24 新農科叫料核對","sources":[{"name":"photo.jpg"}],"rows":[{"date":"2026-10-24","bin":"13","vendor":"新農科","item":"大豬料","tons":4,"note":"中午前到料；林可黴素220ppm、旭維康1kg"}]}
```

sources可附本地照片的SHA-256供辨識來源，不把照片本身、登入資料或雲端權杖寫進清單。跨帳號編輯權限沿用：建立者可核對自己的清單，管理員可核對全部；唯讀帳號只能查看。一般登記人不能藉由草稿覆寫其他人的原叫料。
